4. 多插件同时集成专章（你点名的必答题）

要求重申：日志系统会被多个 dsh 插件同时集成，同时装在 dsh 中，不能因为多装就异常（丢行、串目录、开关互改、散列被劫持、启动即错都算异常）。现状做不到，升级必须先封隔离缺口。

4.1 五层判定（审查票结论原样）

层现状多装会发生什么（已实测）
电话名 prefix部分隔离（唯一有硬门禁）共表则撞名抛错不覆盖；各用各表则静默同名。注册非原子：抛错后表里已留 2 个电话，另 3 个静默缺失。
落盘目录 logDirName部分（靠约定，无校验）覆盖值零校验（'../escaped' 都收）。同名后 A 导出读到 B 的行；A logClear(all) 把 B 的行一起删；同进程共写 5 轮每轮只活 1 行。
开关文件 switchFileName部分（靠约定，无校验）同名后 B 建库即读到 A 的值；最后写者说了算。开关读回一次性，同实例二次不重读。
客户端存储键 dsws.debug不隔离全插件单键，前缀不参与键名，注释自认不参数化。A 开→B 读到 true 且 debug 真入队；B 关/对账把 A 抹成 false。双向可写。
全局函数 dswsLogHash/dswsLogTrunc不隔离调用时实时读全局，一份实现服务全进程。后挂盖先挂，不重建实例即生效，撤掉才回落。

4.2 最危险的三条（多装必踩）

  • 忘传配置 = 落 wf：任何声明 wf 的第三方不写覆盖字段就默认撞 logs / log-switch.json / wf.*，四样全撞且不报错。
  • 扁平 cacheDir 互踩：拿别人的开关文件名当自己的目录名，后来者写盘失败、先到者无损，静默坏。
  • electron-log 对标教训：多实例≠隔离。共享注册表/共享文件/共享 handler 会导致一个实例轮转 rename 掉别人正在写的文件。本包同目录共写更差：读改写无锁，直接整批丢行。

4.3 “不异常”的验收线（升级建议必须写进门禁）

  • 标识互异 + 无覆盖时：目录/开关/电话互相不可见，导出互不串，清空互不删。
  • 标识相同或显式同名时：要么硬报错，要么按租户分桶，绝不静默串行、静默删行、静默改开关。
  • 存储键与全局函数必须命名空间化，否则多装即互改，永远达不到“互不知”。
  • 现有两套单测只有单插件断言且在本仓跑不起来（老 monorepo 路径），隔离层零覆盖——升级必须补双插件对照测试。
