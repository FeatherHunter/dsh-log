# 0.3.0 对抗式自审：原始要求核验、五条质量标准打分与改进方案

日期：2026-10-13　范围：dsh-log@0.3.0（工作树，未提交）
方法：Lead 读源码 + 临时消费方实测 + 独立只读审查子代理（11528560，探针全在 %TEMP%）交叉复现
背景证据：`npm test` 118/118（11 套）、`tsc` exit 0、变异表 37/37 RED（复核者复跑确认，0 SKIP）

## 结论（一句话）

**写侧契约达成且验证扎实（隔离、五键行、轮转、error 分诊、keyset 游标都有可执行断言 + 变异背书），但读侧完整性有一处硬伤、发行面有两处硬伤、error 永不丢在客户端那半边不成立。** 判定：**有条件达成**。

最要命的一条：**封存件对读侧完全不可见**（D1）——轮转一开，`logQuery` / `logExport` / `logClear` 就都看不见被封存的历史行。它直接击穿 #20「查全」、#24「整链不断」、#23「error 可查」三条验收线，而 118 例测试与 37 条变异**全部绿灯**：因为写侧测试断言的是「文件里有多少行」，读侧测试断言的是「查询能查到什么」，**没人测这两者的接缝**。变异测试只能证明「你写下的断言咬得住」，不能发现「你没写的断言」。

## 二、五条质量标准打分

### 1. 符合当前权威 TS 项目里比较优秀的架构和设计 —— **中**（内部强、边界弱）

做得对的：`strict: true` + `noEmit` 类型检查；`as const` 常量表；`export type` 与值导出分离；`src/` 里 `any` / `as any` / `@ts-ignore` / 非空断言 **0 命中**（仅 5 处 `as unknown as Record<string, unknown>` 用于运行时形状校验）；零运行时依赖、依赖全注入。

**硬伤（实测）**：临时消费方（`node_modules` 软链到本仓）用 `strict + moduleResolution: Bundler` 编译：

```
app.ts(1,32): error TS7016: Could not find a declaration file for module 'dsh-log/node'.
  'D:/dsh-plugin/dsh-log/dist/node.js' implicitly has an 'any' type.
tsc-exit:2
```

`npm pack` 11 个文件、0 个 `.d.ts`；`exports` 无 `types` 条件；`import 'dsh-log'` → `ERR_PACKAGE_PATH_NOT_EXPORTED`（无根导出）。**一个纯 TS 项目把类型资产丢在门外**，比任何内部实现细节都更影响「TS 库优秀与否」。

另：无 CI（没有 `.github/`）；`dist/` 入库（`git ls-files dist` 6 个文件）且发布路径没有「入库 dist 与 src 一致」的 gate。

### 2. 从第一性原理出发 —— **强**

关键决策都能追到物理约束，而不是抄来的惯例：

- 文件系统**没有追加原语** → 每次追加都是全文读改写 → 按天分文件把单次覆写体积封顶；再超阈值就封存改名。
- **没有 `async_hooks`**（DSH 双端跑不动）→ 上下文继承只能显式 `log.child(ctx)`，漏传即新链，不假装自动。
- **宿主 fs 能力不可知** → `rename` 作为可选能力协商：有就原子封存，没有就降级继续追加 + `log.rotate.degraded`，绝不「复制 + 截断」冒充原子。
- **跨进程不可知** → 明说风险（README:26）而不是给一个会漏的保证。
- 「记录电话必须如实回包」是从「调用方要据此决策」推出来的。
- 偏移游标被 epoch+物理位置游标否决，且附实测（追加下重复上一页）。

折扣：`200 / 1000 / 5 / 10` 这类常数没有测量依据；**封存件没有被当作一等读侧概念建模**（D1 的根因）。

### 3. 符合 TS 领域高级架构师的思路和设计理念 —— **中偏强**

分层清晰（`config.ts` 纯函数契约 / `store.ts` 落盘引擎 / `phones.ts` 电话层 / `client.ts` 客户端 / `node.ts`+`host.ts` 装配）；失败语义显式冻结；诚实边界写进文档；三入口按运行位置切分（node 同步知目录 → 建库 fail-fast；host 异步问宿主 → 写盘那一刻判）。

扣分：`src/store.ts` **1651 行**、`src/client.ts` **1008 行**上帝闭包；模块级可变单例（`dirHolders`/`dirWaiters`/`sealSeq`，`src/store.ts:148-156`）与「工厂 = 独立实例」的承诺冲突；`export type LogStore = ReturnType<typeof createLogStore>`（23 成员，无分组、无 `@internal`）；43 条常驻事件表两份逐字复制（D5）。

### 4. 专业的数据结构和算法 —— **中**

做得对的：所有权登记 `Map<目录, Map<令牌,{n,permanent}>>`（O(1) 登记/交还，令牌用对象身份）；等待者表 + FIFO 单唤醒 + 200ms 预算（事件驱动替代轮询）；**keyset 游标** `epoch|ts|file|line`（用物理位置当唯一键，追加不移动既有行，同 ts 同内容也分得清）；重试位是有界优先队列的近似（总量上限，优先丢最旧普通行）。

扣分：**读侧文件集合建模错误**（D1）；每页全量读盘 + 解析 + 排序（`src/phones.ts:468-543`），`traceChain` 分支不套 limit（`416` 行算出的 limit 对它形同虚设），14 天 × 5MB ≈ 70MB/页且全量驻留内存；`deferSelfMonRows` 单槽（D13）；`export` 报的 `bytes` 是 UTF-16 码元数而非 `utf8Bytes`（D15）。

### 5. 符合优秀的设计模式 —— **中偏强**

工厂（`createLogStore`/`createClientLog`/`createQuickLog`/`createNodeHostLog`）+ DI（fs/timer/storage/host 全注入）+ 策略（`LogFileService`/`LogPlatform` 能力协商）+ 观察者（`setOnDrop`/`emitOnDrop`）+ 适配器（`node.ts` 把 `node:fs` 抹成 target 对象）+ 命名空间化（`synced.beforeExit`）。

扣分：全局单例状态；**接口被测试塑形**（`ClientLog` 把 `logQueue`/`logDroppedState`/`logForwardState`/`logFlushTimer`/`hash8`/`estimateBatchBytes`/`maybeForwardSummary`/`watchSwitchOp` 全放进公共接口，注释直言「活引用（测试与调用处可直接读）」）；deprecated 空转函数（名字在、效果无）。

## 四、推荐方案

### 0.3.1「补洞 + 发类型」（建议立即做，半天量级）

1. **D1 读侧文件集合建模**（最高优先）：在 `config.ts` 单源定义 `readableLogPattern = /^\d{4}-\d{2}-\d{2}(\.\d+)?\.log$/`，`phones.ts` 的 `matched` 与 `clear` 保护集都改用它；封存件参与查询/导出/清空，按 (日期, 序号) 排序保证顺序。**验收线要升级成接缝断言**：同一用例里既数文件行数、也数查询行数，两者必须相等；再加「封存后 `logClear({date:'all'})` 能删封存件、当日文件与 audit 不动」「整链跨封存件不断」两条。这正是本轮漏掉的那条接缝。
2. **D8 + D9 类型发行**：`tsconfig` 加 `declaration + emitDeclarationOnly + declarationDir`，`build.mjs` 加一步声明产出；`exports` 每个子路径改条件导出 `{ "types": ..., "default": ... }`；同时解决 ambient 冲突（要么把 `node-ambient.d.ts` 改成不与内建同名的适配层，要么加 devDependency `@types/node` 走标准形状）。验收：临时消费方 `strict` 编译 0 错误；根入口要么可用、要么 README 写明没有。
3. **D2 + D3 客户端诚实与重试**：`dropped += rejected`（不再整批计）、`accepted/skipped` 进转发汇总行；失败批次 `unshift` 回队首 + 有界退避（照 `store.scheduleRetry` 的做法）。同步改 `.local/mutation-check.ps1` 的 M32/M33 锚点与预期。
4. **D4 `sampleRate`**：让它真采样（普通行按比例抽、error/warn/常驻不受影响），或从 `setSwitch` 契约里删参并写进 README。推荐实现采样——开关文件形状不变，行为与文档一致。
5. **收尾小修**：D5 单源化、D10 删 shim、D16 的 README 两处示例与 tsconfig 注释。

### 0.3.2「收口」（半天）

D6 租约公平性（有等待者时禁止插队，约 5 行）、D7 读侧按日期剪枝 + 流式解析 + `traceChain` 显式截断标记、D11/D12 接口收窄（行为方法 + 只读视图 + `@internal`）、D13/D14/D15 小修、D16 加 `check:dist`（构建到临时目录与入库 dist 逐字节比对）并接 CI。

### 0.4.0「架构」（评估后做）

拆 `store.ts`（隔离登记 / 队列与重试 / 轮转与审计 / 装配四块，`createLogStore` 只做装配）；去掉模块级全局状态（改成注入的注册表或实例持有），让「工厂 = 独立实例」名副其实；查询加按天索引或流式扫描。

**不建议改的（做得对，别动）**：按天分文件 + 能力协商式 rename 降级；keyset 游标；诚实回包形状；写失败进重试位；`synced()` 唯一动词；诚实边界写进 README；变异表 + 真子进程 SIGKILL 用例。这套验证基建是本项目最值钱的部分——**但本轮也证明它有边界：它只能守住你写下的断言，守不住你没写的接缝**。
